# Kohana 3.1: перевірене локальне встановлення

Дата перевірки: 20 жовтня 2026 року.

## Середовище

- Windows 10 Enterprise, 10.0.19045.
- Hermes Python package 0.18.2, Python 3.11 у його власному venv.
- Корінь Hermes: `C:\Users\User\AppData\Local\hermes`.
- Ядро: `hermes-agent`, commit `449706cb` від 2026-07-09.
  Checkout уже мав численні локальні зміни до початку налаштування.
  Ядро не перевстановлювалося й не редагувалося.
- Desktop: Electron, package.json у checkout має версію 0.17.0;
  це версія джерел оболонки, не незалежна перевірка версії запакованого exe.
  Виконуваний файл: `hermes-agent\apps\desktop\release\win-unpacked\Hermes.exe`.
- Desktop logs підтверджують використання цього самого Python venv через `hermes serve`.
- Модель: `gpt-oss:120b`, provider `ollama-cloud`, endpoint `https://ollama.com/v1`.
- Репозиторій Kohana клоновано з upstream commit `a6f6c78b87504514833e0359ce1605ff72ac9d08`.

## Профіль і запуск

Робочий профіль: `C:\Users\User\AppData\Local\hermes\profiles\kohana-v3_1`.
Використано стандартний каталог іменованих профілів Hermes для виявлення desktop.
Раніше описаний `.kohana/hermes-v3_1` не створювався: це був би інший профіль.

**Desktop:** відкрий наявний Hermes, вибери `kohana-v3_1` і створи нову розмову.
`%APPDATA%\Hermes\active-profile.json` налаштовано на цей профіль.
Запущений desktop backend через `/api/status` фактично повернув цей `hermes_home`.
Старі розмови default не перетворюються на розмови Кохани.

**Перевірений незалежний запуск:** двічі відкрий `launch-kohana.cmd` у корені
цього репозиторію. Він запускає встановлений Hermes з явним `-p kohana-v3_1`.
Або виконай `hermes -p kohana-v3_1 chat --cli`.
Запускник розраховано на це локальне розташування репозиторію.

Основні `config.yaml`, `.env`, `SOUL.md` Hermes збережено без змін
(підтверджено SHA-256). Налаштування моделі скопійовано в новий профіль.
Ключ скопійовано локально, не виводився в звіт і не потрапляє до Git.
Додаткові іменовані personalities вилучено лише з конфігурації Кохани.

## Persona

`persona/persona_kohana_v3_1.xml` → наявний `render_persona()` → профільний `SOUL.md`.
XML 3.1 не редагувався. XML 3.0 не змінено (перевірено SHA-256).
Unit-тести перевіряють збереження кожного текстового листка XML.

Перевірено справжній `AIAgent._build_system_prompt()`: усі 15184 символи
SOUL без завершального переносу містяться в промпті точно один раз.
Обрізання немає. `agent/system_prompt.py` використовує SOUL замість стандартної
ідентичності. Службові правила інструментів Hermes залишаються чинними.
Нові правила характеру не додавалися.

## Пам'ять

Встановлена версія підтримує `MemoryProvider`. Плагін `kohana_sqlite`
розгорнуто у `profiles/kohana-v3_1/plugins/kohana_sqlite`.
Його реалізація використовує наявний `MemoryStore`; ядро Hermes не змінюється.
Активність провайдера та інструмента `kohana_memory_search` перевірено в AIAgent.

Для явного запису надішли окремим повідомленням:

> Запам’ятай: Важливий контекст, який потрібно зберегти.

Після завершення відповіді Hermes передає репліку у `sync_turn`.
Зберігається лише текст користувача з цим префіксом, до 4000 символів,
із джерелом `user-explicit:<session_id>`. Відповіді моделі не перетворюються
на факти. Наступні сесії отримують останні 20 нотаток автоматично;
старіші доступні через буквальний пошук. Це не семантична пам'ять.
База: `profiles/kohana-v3_1/kohana-memory.db`.
Нотатки позначаються як дані та твердження користувача, не перевірені факти.
Промптова заборона виконувати інструкції з пам'яті не є sandbox.

Стандартні `memories/MEMORY.md`, `memories/USER.md` також залишилися увімкненими;
це окремий механізм Hermes, де записи робить модель через його memory tool.
Історія сесій Hermes зберігається у профільному `state.db` та `sessions/`.
Приватні чати з інших сервісів не імпортувалися.
Тестова нотатка «Ліхтар-7319» залишена й явно позначена як тестова.

## Фактичні перевірки

- 10/10 unit-тестів Kohana, включно з двома новими тестами provider:
  запис → новий екземпляр → recall; відсутність запису вигадок assistant;
  заборона запису для контексту subagent.
- Реальний API Ollama через Hermes: знайомство, романтична репліка,
  технічне заперечення з сарказмом, підтримка виснаженого користувача,
  чесне незнання невідомого особистого факту, зупинка видалення backup.
- Запис тестового коду та відновлення в окремому процесі/новій сесії.
- Додатковий запит про помилки Python: правильно уточнено `ZeroDivisionError`,
  `decimal.DivisionByZero` та обмеження перехоплення `SyntaxError`.
- Desktop backend запущений і повідомляє правильний профіль.
  Діалоги тестувалися через CLI того самого ядра, не кліками в desktop.
  Захищені desktop endpoints без його внутрішнього токена повертають 401;
  їх успішну перевірку не заявлено.
- Додаткові upstream pytest-тести Hermes не виконалися: у його venv немає pytest.
  Це не стосується успішних 10 unit-тестів Kohana.

Локальні результати: `.kohana/validation/dialogs.json`, `prompt-check.json`,
`desktop-check.json`. Ці файли не додаються до Git.

## Обмеження

Невеликий набір діалогів не гарантує стабільності кожної наступної відповіді.
Технічна відповідь про `except: pass` була надмірно довгою та спочатку
неточно згадала `SyntaxError`/`DivisionByZero`; окрема перевірка дала коректне
уточнення. Відповідь про очищення диска запропонувала Linux-інструменти на Windows.
Затверджений характер не переписувався заради маскування цих обмежень моделі.
Нова пам'ять потребує явного «Запам’ятай:»; автоматичного виділення фактів
із довільної розмови цей SQLite-провайдер не робить.
Запис виконується після завершення відповіді: при аварії чи обриві він може
не відбутися, навіть якщо модель уже сказала «запам'ятала».

## Повернення попередньої конфігурації

Вибери `default` у Hermes. Для CLI: `hermes -p default chat --cli`.
Якщо треба скинути лише вибір desktop, після його закриття встанови
`{"profile":"default"}` у `%APPDATA%\Hermes\active-profile.json`.
Старий профіль і його пам'ять не змінювалися.

Backup початкових config, .env, SOUL і контрольні суми:
`.kohana/backups/initial/`. Він містить секрети: не публікуй і не пересилай його.
До цього налаштування `active-profile.json` був відсутній.
Профіль Кохани можна залишити на диску; видалення для відкату не потрібне.

## Змінені файли

У репозиторії: `src/kohana_agent/memory.py`, нові `hermes_memory.py`,
`tests/test_hermes_memory.py`, `launch-kohana.cmd`, цей документ, посилання в README та уточнення у HERMES.md і VALIDATION.md.
Розгорнутий плагін є копією коду: після змін вихідного провайдера його потрібно
повторно розгорнути й перезапустити Hermes; автоматичного оновлення немає.
Поза репозиторієм: новий профіль `profiles/kohana-v3_1`,
desktop `active-profile.json`. Git push не виконувався.
