# Технічна архітектура

## Мета

Спочатку персональна співрозмовниця з послідовним характером і пам'яттю, з подальшим додаванням технічних дій. Це стартове проєктне рішення, яке можна змінити без форку Hermes.

## Компоненти

| Компонент | Зараз | Ціль |
| --- | --- | --- |
| Persona | XML → Markdown SOUL.md | Версіонування, перевірки поведінки на наборах діалогів |
| Профіль | Новий каталог для Hermes | Перевірений профіль із зафіксованою версією рушія |
| Runtime | Не включений | Hermes: цикл, модель, інструменти, сесії |
| Пам'ять | Окремі ручні SQLite-нотатки | Memory provider із пошуком і контрольованим записом |
| Дозволи | Немає виконавця команд | Контроль перед кожною реальною дією та ізоляція |
| LLM | Не підключена | Спочатку API; локальний endpoint після вимірювання ресурсів |
| UI | CLI для підготовки | Чат, далі голос; транспорт обрати після перевірки upstream |

## Потоки даних

Підготовка: XML перевіряється локально, перетворюється на Markdown та записується в новий профіль. Усі секції, атрибути та приклади переносяться; це синтаксична перевірка, не аудит змісту довільного XML. Користувач має перевіряти інструкції перед використанням.

Поточна пам'ять: явна команда користувача → параметризований SQL → локальна база. Пошук повертає лише вказаний підрядок і, за потреби, конкретний проєкт. Автоматичного захоплення діалогів чи передавання в LLM немає.

Майбутня сесія: UI → Hermes → LLM → пропозиція дії → контроль дозволів → інструмент → фактичний результат → відповідь. Зовнішня пам'ять передаватиметься обмеженими релевантними фрагментами з походженням, а не повним архівом.

## Дані та приватність

Профіль Hermes містить компактні `USER.md` і `MEMORY.md`, а історію сесій веде upstream. Наша база поки зберігає лише ручні нотатки. Це різні джерела: не дублювати всю історію та не створювати двох незалежних версій одного факту.

Схема v0.1: `notes(id, project, content, source, created_at)`. Ідентифікатор і час створює база; текст та джерело надає користувач. Зміна схеми потребуватиме версіонованих міграцій. Редагування, видалення, експорт, retention, шифрування та резервне копіювання ще не реалізовані; перед особистим довготривалим використанням додати їх.

## Межі довіри

Persona та AGENTS.md — інструкції, не механізм sandbox. `HERMES_HOME` — каталог даних, не ОС-ізоляція. Права 0700/0600 корисні на POSIX, але не заміняють ACL, шифрування та захист від процесів того самого користувача.

Тексти сайтів, файлів, нотаток і tool output — недовірені дані. Майбутній адаптер не повинен виконувати інструкції з пошукової видачі як системні правила. Видалення файлів, розсилки, публікації, зміна доступів і встановлення програм потребують окремого механізму дозволів та журналу результатів. До його реалізації Kohana не запускає інструменти сама.

## Сумісність і обмеження

Власний код: Python 3.11+, стандартна бібліотека. Перевірене середовище початкової розробки: Linux, Python 3.12. Інші версії перевірятиме CI. Не визначаємо сумісність LLM за назвою відеокарти: потрібні конкретна модель, формат квантування, контекст і вимірювання RAM/VRAM.
