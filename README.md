# Кохана / Kohana Agent

Репозиторій: [BOHDANMARCEN/giorl-ai-agent](https://github.com/BOHDANMARCEN/giorl-ai-agent). Назва Python-пакета й CLI: `kohana-agent` та `kohana`.

Персональна AI-співрозмовниця й технічна напарниця на базі **Hermes Agent**, із власною Persona 3.0 та довготривалою пам'яттю.

**Стан: 0.1.0 — технічна основа.** Це ще не готовий чат і не автономний агент. Репозиторій містить працездатні офлайн-утиліти: генерацію профілю Hermes та окреме SQLite-сховище нотаток. Рушій Hermes, LLM, голос та GUI сюди поки не інтегровані.

## Системна інструкція

Повний оригінал: [persona_kohana_v3.xml](persona/persona_kohana_v3.xml). Файл збережено без змін і скорочень; це джерело істини для генерації `SOUL.md`.

### Persona 3.1 — окрема версія для експериментів

[Persona Kohana 3.1](persona/persona_kohana_v3_1.xml) — альтернативна, більш романтична й спонтанна версія з гострішим, але доброзичливим сарказмом «Сучка 2.0». Оригінальну [Persona 3.0](persona/persona_kohana_v3.xml) не змінено. CLI підтримує обидві версії та вказує правильну версію у заголовку `SOUL.md`.

Для **нового окремого профілю** (команда не змінить профіль, який уже існує):

```bash
kohana init --home .kohana/hermes-v3_1 --persona persona/persona_kohana_v3_1.xml
```

Якщо в тебе Hermes уже налаштований, не перезаписуй його чинні `SOUL.md`, `USER.md`, `MEMORY.md` чи конфігурацію провайдера автоматично. Спершу перевір `SOUL.md` у новому профілі, зроби резервні копії й лише після цього підключай його у своєму середовищі. Запуск конкретного desktop-клієнта, Ollama Cloud і завантаження повної Persona 3.1 ще не проходили end-to-end перевірку в цьому репозиторії.

## Що вже реалізовано

- Python CLI без сторонніх runtime-залежностей, Python 3.11+.
- Перевірка XML Persona 3.0 та детермінована генерація читабельного `SOUL.md` зі збереженням розділів і прикладів.
- Створення **нового** профілю: `SOUL.md`, `memories/USER.md`, `memories/MEMORY.md`.
- Відмова, якщо каталог профілю вже існує; наявні профілі не змінюються.
- SQLite-нотатки: текст, проєкт, джерело та час UTC; пошук за буквальним підрядком із фільтром проєкту.
- Офлайн-діагностика, unit-тести та конфігурація GitHub Actions.

## Швидкий старт

Виконуй команди з кореня цього репозиторію. На Windows починай із WSL2; нативний Windows та запуск Hermes у цьому середовищі не перевірені.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
kohana doctor
kohana init --home .kohana/hermes --persona persona/persona_kohana_v3.xml
```

`init` не встановлює Hermes, не завантажує модель і не звертається до мережі. Якщо `.kohana/hermes` вже існує, обери новий каталог; автоматичного перезапису немає. У разі помилки диска може залишитися частково створений новий каталог: перевір його перед повторенням.

Пакет встановлює тільки CLI; джерело XML залишається у репозиторії, тому шлях передається явно через `--persona`.

### Підключення до встановленого Hermes

Встанови Hermes окремо за [офіційною інструкцією](https://hermes-agent.nousresearch.com/docs/getting-started/installation). Для цього проєкту ще не вибрано й не протестовано конкретний upstream commit; сумісність API не гарантується.

Після встановлення, у тому самому shell із кореня Kohana:

```bash
export HERMES_HOME="$PWD/.kohana/hermes"
hermes setup
hermes
```

Ці команди — рекомендований ручний шлях інтеграції, **не результат виконаного end-to-end тесту**. `hermes setup` налаштовує модель і провайдера у виділеному профілі; ключі не додавай до Git. Вартість і передавання даних залежать від обраного провайдера. Вміст `SOUL.md` може проходити перевірку й обрізання в Hermes; фактичне завантаження Persona потрібно перевірити в інтеграційному етапі.

`HERMES_HOME` розділяє дані профілів, але **не ізолює процес від ОС**. Перед роботою з інструментами окремо налаштуй і перевір середовище виконання Hermes. Kohana зараз не контролює його tool calls.

### Локальні нотатки

```bash
kohana memory --db .kohana/memory.sqlite3 add \
  'Для прототипу обрано Hermes без форку ядра.' \
  --project kohana --source 'рішення користувача'
kohana memory --db .kohana/memory.sqlite3 search 'Hermes' --project kohana
```

Це **окреме** сховище, не база діалогів Hermes. Hermes ще не читає ці нотатки автоматично. Пошук чутливий до регістру, буквальний, без embeddings та ранжування. `source` — наданий автором опис походження, а не автоматична перевірка достовірності. SQLite не зашифрована; не записуй сюди секрети.

## Перевірка

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

Або після встановлення пакета: `python -m unittest discover -s tests -v`.
Локальні тести не перевіряють LLM, інструменти Hermes, якість характеру чи ізоляцію. GitHub Actions запуститься після завантаження репозиторію на GitHub.

## Напрям розвитку

Наступний крок — зафіксувати версію Hermes й перевірити повний діалог із Persona. Далі підключити зовнішні нотатки через підтримуваний memory provider, додати походження та видалення фактів, перевірити контроль інструментів. Після цього — інтерфейс і голос. Докладніше: [план робіт](docs/ROADMAP.md).

Особистість задає стиль. Пам'ять зберігає факти. Дозволи повинні контролюватися кодом і середовищем виконання. Накопичення досвіду й skills не означає перенавчання ваг моделі.
